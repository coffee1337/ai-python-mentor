# UI: путь из 15 уроков

Краткая спецификация для dashboard и страницы «Учебный путь». Это дизайн-модель для маршрута курса; названия, порядок, длительность и статусы всегда берутся из авторского плана API — интерфейс не дополняет отсутствующий контент фиктивными уроками.

## Направление

Сохранить текущий спокойный editorial-язык: бумажный фон, зелёный акцент, заголовки Georgia, тонкие разделители и свободная типографика. Путь — упорядоченный список, не график и не набор тяжёлых карточек. Последовательность из 15 уроков видна целиком как линейный маршрут; группировать можно только по реальным разделам курса. Позиции 01–15 — навигационные номера, а не оценка или mastery.

## Dashboard

- Одна компактная секция «Продолжить обучение»: название следующего доступного урока, его длительность (если есть в данных), короткая причина/prerequisite-контекст и заметная ссылка «Продолжить». Ведёт на этот урок.
- Рядом или ниже — спокойная сводка «Завершено: X из Y уроков» только когда X и Y получены из актуального пути. Не показывать процент, кольцевой индикатор, пустой график или формулировки про «успеваемость».
- Ссылка «Весь учебный путь» открывает полный список. Можно показать до трёх ближайших реальных уроков, но не вторую конкурирующую ленту AI-плана.
- Если нет рекомендуемого урока, различать «нужно пройти диагностику» и «все уроки текущего маршрута завершены» по ответу API; не выводить общий факт «курс окончен», если завершён только персональный маршрут.

## Страница плана

Заголовок «Учебный путь Python», под ним фактическая подпись «Завершено X из Y уроков» и однострочное пояснение, что следующий урок открывается после необходимых основ. Основной контент — нумерованный список в серверном порядке, с тонким вертикальным направляющим штрихом на широком экране. Никакая связь prerequisite не должна читаться только по цвету или геометрии.

Каждая строка содержит: номер и заголовок; метку состояния словами; длительность при наличии; короткое объяснение блокировки для locked. Действие доступно только для available. Завершённые строки остаются в маршруте, чтобы сохранялась последовательность; их можно открыть повторно, если это разрешает сервер.

| Состояние | Отображение и действие |
|---|---|
| Завершён (completed) | Текстовая метка «Завершён» и нейтральный check; без оценки/процента. Ссылка на повторение — только если урок разрешён сервером. |
| Доступен (available) | Метка «Доступен»; единственная первичная кнопка/ссылка — «Начать» или «Продолжить» для следующего шага. Другие доступные уроки остаются ссылками без равнозначного CTA. |
| Заблокирован (locked) | Метка «Пока закрыт»; неинтерактивная строка, без вида disabled-ссылки. Показать конкретное условие: «Сначала завершите “{название prerequisite}”». Если причина не пришла от API — честно написать «Станет доступен после предыдущего урока» только когда порядок это гарантирует; иначе не угадывать. |

Для 15 реальных шагов список не сворачивать по умолчанию: ученик видит, что впереди, но будущие шаги явно помечены как закрытые. Не показывать оценку курса как «15 уроков пройдено» до получения total=15 от актуального плана. Если авторских уроков пока меньше, показывать только фактически доступный маршрут и при необходимости нейтральную заметку о том, что каталог будет расширен — не пустые placeholders 03–15.

## Состояния страницы

- **Loading:** текст «Загружаем учебный путь…» и спокойные строки-заглушки без имитации заполненного прогресса.
- **Error:** короткое сообщение для ученика и действие «Повторить»; не заменять ошибку пустым маршрутом.
- **Empty:** если уроков нет — объяснить, что маршрут ещё не сформирован, и дать уместный следующий шаг (диагностика/настройка, если это указано API). Пустой график не рисовать.
- **Assessment required:** отдельное состояние с пояснением и ссылкой на диагностику, не выдавать его за empty-каталог.
- **Success, всё завершено:** «В текущем плане больше нет незавершённых уроков»; оставить завершённую последовательность и предложить только доступное действие (например, повторение), не придумывать следующий урок.
- **Disabled / locked:** причина видна рядом с названием; клавиатурный фокус не попадает на неактивные элементы.

## Мобильность и доступность

На узком экране направляющий штрих и отступы упрощаются в обычный вертикальный список; заголовки и причина блокировки переносятся без горизонтальной прокрутки. Номер шага не заменяет заголовок. Состояние передаётся текстом и доступным именем; декоративный check скрыт от screen reader. Семантика — ordered list, заголовки в логическом порядке, focus видим, цели касания не меньше 44px. Не полагаться на цвет; учитывать prefers-reduced-motion и не анимировать заполнение прогресса.

## Данные и границы реализации

Текущий frontend уже получает у /learning/path статусы completed | available | locked, completed, total и next_lesson_id; dashboard также использует персональный /learning/plan. Для точной подписи блокировки нужен prerequisite (например, blocked_by с ID и отображаемым названием), а для общего маршрута dashboard — единый актуальный список, иначе его нельзя безопасно синхронизировать с персональным планом. Клиент не выводит заблокированный урок по догадке и не подменяет серверный статус: если prerequisite-метаданных нет, оставить статус без выдуманной причины и согласовать контракт с backend.
