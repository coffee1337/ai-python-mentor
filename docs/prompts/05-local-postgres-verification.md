# Промт 05 — Локальный PostgreSQL вместо Docker

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md` и `.agents/skills/migration-safety/SKILL.md`. Инструкции агента `devops` лежат в `.codex/agents/devops.toml` — отдельного скилла `devops` в проекте нет.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Промт 00 **уже выполнен**: инструкции синхронизированы с кодом, baseline записан. Не проверяй его и не спрашивай про него — работай дальше.

На этой машине **виртуализация не работает**. Проверено: гипервизор обнаружен, но WSL2 и Hyper-V недоступны, `wsl --status` предлагает `wsl --install --no-distribution`, `docker version` не соединяется с daemon (pipe `dockerDesktopLinuxEngine` отсутствует), дистрибутивов WSL нет, локального PostgreSQL нет.

Следствие: все 33 теста проходят на SQLite через фикстуру `client` в `apps/api/tests/test_auth.py` (`create_engine("sqlite://")` + `StaticPool`). Функции, специфичные для PostgreSQL, **не проверяются вообще**:

- `with_for_update()` — используется в `mentor.py` для сериализации запросов на пользователя и в `skill_evidence.py` для сериализации обновления mastery. На SQLite это фактически no-op;
- `ON DELETE CASCADE` и `SET NULL` — SQLite по умолчанию не проверяет внешние ключи;
- уникальные ограничения и поведение при гонках.

`ci.yml` это покрывает — там сервис `postgres:17-alpine` и round trip миграций. Но локально правки в этих областях проверить нельзя.

## Задача

**1. Установи и настрой PostgreSQL 17.**

Дай `devops` задачу. Проверено, что пакет доступен: `winget search --id PostgreSQL.PostgreSQL` показывает версии до 18, нужна 17.

Требования:

- установка через `winget`, без Docker и без WSL;
- служба стартует автоматически и не требует перезагрузки;
- база и пользователь так, чтобы строка подключения совпадала с `.env.example`: `postgresql+psycopg://mentor:mentor_local_only@localhost:5432/mentor`;
- пароль — только локальный для разработки, тот же, что в `.env.example`. Не меняй `.env.example` и не добавляй секреты в репозиторий;
- шаги установки в README отдельным разделом.

**2. Прогони то, что до этого не проверялось.**

Дай `tester` задачу на реальной базе:

```
cd apps/api
$env:DATABASE_URL="postgresql+psycopg://mentor:mentor_local_only@localhost:5432/mentor"
python -m alembic upgrade head
python -m alembic check
python -m alembic downgrade 0001_initial
python -m alembic upgrade head
python -m pytest -q
```

Попроси `tester` **доказать**, какая база использовалась, а не предположить. Если фикстура жёстко переопределяет `get_db` на SQLite — тесты на PostgreSQL так не поедут, и это нужно назвать явно.

**3. Добавь тесты на то, что SQLite не проверяет.**

Целевые тесты на поведение, специфичное для PostgreSQL:

- две параллельные записи evidence для одного пользователя сериализуются через `with_for_update` и не приводят к потере обновления;
- ограничение уникальности действительно срабатывает;
- `ON DELETE CASCADE` удаляет дочерние записи.

Пометь тесты так, чтобы они **пропускались** на SQLite и запускались только на PostgreSQL — иначе они станут ложноположительными. Предусмотри переменную окружения для переключения.

**4. Зафиксируй разницу.**

Дай `devops` задачу обновить `.agents/skills/verification-strategy/SKILL.md` и раздел «Проверки» в README: что теперь проверяется локально, а что всё ещё нет.

## Ограничения

- **Не включай и не чини Docker.** Виртуализации нет, это вне задачи. Убери Docker Desktop из активного контекста, чтобы проверки не пытались к нему обращаться.
- Не трогай `.env.example` и не добавляй секреты в репозиторий.
- Runner не разворачивай: он fail-closed и требует отдельного Linux-хоста с изоляцией, а не локальной БД.
- Не добавляй `pytest-postgresql` и аналогичные зависимости без необходимости — нативная установка проще.
- Не ослабляй тесты ради прохождения: упал на PostgreSQL — разбирайся с причиной, а не с ожидаемым значением.
