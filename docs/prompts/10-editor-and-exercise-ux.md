# Промт 10 — Редактор кода и упражнения

## Роль

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md`, `.agents/skills/frontend-implementation/SKILL.md`, `.agents/skills/ui-design-system/SKILL.md` и `.agents/skills/learning-domain/SKILL.md`.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Все промты 00–09 выполнены. Курс покрывает `python.core` и фазу 1 `python.backend`.

В P0 спецификации есть **Monaco editor**, и сейчас его нет: в `apps/web/app/learning/page.tsx` поле кода — обычный `<textarea id="source-code" className="code-editor">` со `maxLength={20000}` и `spellCheck={false}`. Это не редактор кода, а поле ввода. Упражнения существуют, но писать в них неудобно.

Одновременно с этим страница урока неуправляема: она рендерит разметку одним файлом, и по README уже есть отдельные компоненты `course-path.tsx`, `mentor-chat.tsx`, `review-today.tsx`, которые на неё ссылаются.

Принятые решения — в `docs/decisions.md`. Визуальный язык — в `.agents/skills/ui-design-system/SKILL.md`.

## Задача

### 1. Спроектируй редактор

Дай `architect` задачу выбрать редактор и обосновать решение письменно. Кандидаты: Monaco (`@monaco-editor/react`) или CodeMirror 6. Требования:

- подсветка синтаксиса Python и автоотступы;
- работа в Next.js 15 App Router и React 19;
- не ломает `npm run build` и не тянет SSR-несовместимые пути — это главный риск Monaco;
- весит разумно: страница урока не должна грузить мегабайты ради поля ввода;
- доступен с клавиатуры и имеет видимый фокус;
- уважает `prefers-reduced-motion` и тёмную тему существующего дашборда.

### 2. Реализуй редактор

Дай `frontend-implementer` задачу реализовать выбранный вариант как отдельный компонент с чистым контрактом: значение, `onChange`, ограничение длины, `disabled`, `aria`-атрибуты. Учти, что лимит 20 000 символов сейчас держится на `textarea` — перенеси его в компонент.

### 3. Переработай страницу урока

Дай `frontend-implementer` задачу разбить `apps/web/app/learning/page.tsx` на компоненты по домену: `LessonTheory`, `LessonPractice`, `KnowledgeCheckSection`, `AttemptHistory`, `CoursePath`. Файл сейчас перегружен и является худшим местом проекта.

Правила по содержанию:

- показывай состояние Runner честно: код сохраняется, но не исполняется; не обещай проверку, которой нет;
- не показывай проценты mastery как факт уровня;
- состояния загрузки, ошибки и пустого результата — по текущим правилам доступности проекта;
- `spellCheck` и автосохранение черновика попытки — на усмотрение implementer, но без молчаливой потери текста.

### 4. Проверь доступность и качество

Дай `tester` задачу проверить: редактор доступен с клавиатуры, фокус виден, `disabled` работает, лимит длины соблюдается, страница не падает при отсутствии результата.

Дай `ui-designer` задачу проверить визуальный язык: отступы, типографика, состояния кнопок, тёмная тема, контраст.

## Ограничения

- **Не подключай исполнение кода.** Runner fail-closed, вкладка «выполнить» по-прежнему недоступна.
- Не расширяй scope: только редактор и страница урока.
- Не ломай существующие маршруты `/learning`, `/dashboard`, `/assessment`, `/path`.
- Не добавляй клиентскую валидацию, которая противоречит серверной: сервер решает, что верно.
- `npm run lint` и `npm run build` должны остаться зелёными.

## Критерий готовности

Поле кода — настоящий редактор с подсветкой Python, страница урока разбита на компоненты, доступность проверена, `npm run lint` и `npm run build` зелёные.

В отчёте укажи: выбранный редактор и почему, изменённые файлы, точный вывод проверок, размер бандла до и после, что осталось непроверенным.
