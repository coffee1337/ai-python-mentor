# Промт 02 — Лестница подсказок

## Роль

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md`, `.agents/skills/learning-domain/SKILL.md` и `.agents/skills/api-contract-design/SKILL.md`.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Промт 00 **уже выполнен**: инструкции синхронизированы с кодом, baseline записан. Не проверяй его и не спрашивай про него — работай дальше.

Центральная гипотеза продукта: наставник учит, а не делает работу за ученика. Сейчас это предположение **не защищено кодом**.

- `record_evidence` в `apps/api/app/skill_evidence.py` принимает `assisted: bool` и `hint_count: int`, но вызывающие места передают `assisted=False, hint_count=0` — в `assessment.py:92` и `knowledge_check.py:54`.
- Ученик может получить готовое решение в mentor-чате, и mastery это никак не отразит.
- В `ai_curriculum.py` есть валидатор `no_solution_text`, который запрещает маркеры вроде `решение:` и `правильный ответ` в тексте урока. Это полезный прецедент: запрет на утечку решения уже есть, распространи подход.

Принятые решения — в `docs/decisions.md`, раздел «Assisted и independent разделены всегда».

## Задача

**1. Спроектируй доменную модель.**

Дай `architect` задачу: как описать лестницу подсказок так, чтобы непротиворечиво помещалась в существующий `SkillEvidence` и не ломала версионирование контента. Отдельно реши: подсказки принадлежат уроку (контент) или упражнению.

Требуемые уровни по спецификации: направление → концепция → шаг → псевдокод → решение. Уровень 0 — без подсказки.

**2. Спроектируй контракт.**

Дай `api-designer` задачу на основе схемы от `architect`. Учти: клиент не передаёт user ID; раскрытие подсказки — изменяющее состояние, значит CSRF; ответ не содержит ключей и внутренних идентификаторов.

Продумай поток без готового решения из коробки:

- Ученик нажал «получить подсказку» → сервер записал факт использования подсказки → вернул текст **одного** следующего уровня.
- Ученик дошёл до уровня решения → `independent_score` не может остаться 1.0.
- Повторное открытие того же уровня не должно повторно засчитываться как новая помощь, если это тот же уровень того же упражнения.

**3. Реализуй по миграции, затем API, затем домен.**

Порядок обязателен: сначала миграция и модель, потом эндпоинты, потом запись в evidence. Дай `implementer` последовательные задачи.

Ключевые требования:

- запись использования подсказки — append-only, как и весь `SkillEvidence`;
- `assisted=True` при любой использованной подсказке;
- `hint_count` — фактическое число раскрытых уровней, не номера и не «использовалась или нет»;
- полное решение — отдельный уровень, после него дальнейшая практика обязана быть без подсказок;
- неизвестный уровень, чужое упражнение и повторное раскрытие — контролируемые ошибки, не 500;
- контент с подсказками версионируется вместе с уроком.

**4. Покрой тестами.**

Дай `tester` задачу: тест на постепенность раскрытия; тест на то, что `independent_score` снижается; тест на то, что чужой user ID не позволяет раскрыть подсказку; тест на CSRF. Миграцию проверь round trip: `upgrade head` → `downgrade` до предыдущей ревизии → `upgrade head`, на SQLite через временный файл.

**5. Открой вопрос к домену.**

Попроси `architect` явно ответить: должна ли подсказка из mentor-чата учитываться как evidence. Если да — пусть это будет отдельная задача с пометкой, что она меняет доменное поведение.

## Ограничения

- Docker и PostgreSQL не работают. Round trip миграций — на SQLite, временный файл, удалить после проверки.
- Не включай Runner: он fail-closed, код ученика не исполняется.
- Не отдавай полное решение автоматически и не делай «кнопку показать ответ» без записи в evidence.
- Не своди mastery к проценту: assisted и independent показываются раздельно.
- Не меняй `PASS_SCORE` и не ослабляй проверку `knowledge_check`, чтобы тесты прошли.

## Критерий готовности

Лестница раскрывается по одному уровню, использование подсказок попадает в append-only evidence, `assisted` и `hint_count` не всегда нулевые, чужой прогресс недоступен, миграция обратима, `pytest` и `npm run lint` зелёные.

В отчёте укажи: изменённые файлы, точный вывод проверок, ответ `architect` про mentor-чат, что осталось непроверенным.
