# Промт 00 — Синхронизация инструкций с кодом

## Роль

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md` и `.agents/skills/verification-strategy/SKILL.md`.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Проект: Next.js 15 + FastAPI + PostgreSQL в modular monolith. Уже есть 13 агентов, 12 скиллов, CI, `docs/decisions.md`, `docs/eval/tasks.md`.

Принятые решения — в `docs/decisions.md`. Прочитай их до проектирования: большинство архитектурных развилок уже закрыто, и предлагать переделки без причины не нужно.

Состояние кода на момент написания промта (исторический snapshot; календарная дата написания здесь не зафиксирована, числа миграций/моделей, лимиты и gaps ниже не описывают текущий worktree):

- 13 миграций Alembic, последняя — `0014_ai_usage_ledger_user_index`. `alembic check` проходит.
- 27 моделей в `apps/api/app/db/models.py`, включая `SkillEvidence`, `SkillMasteryAudit`, `AIUsageLedger`.
- `skill_evidence.py` принимает параметры `assisted` и `hint_count`, но никто их не передаёт: в `assessment.py` и `knowledge_check.py` стоит `hint_count=0`.
- В `ai_curriculum.py` есть полноценный учёт в `AIUsageLedger` с токенами, кэшем и лимитом 10 вызовов в час.
- В `mentor.py:104` вызывается `ai_gateway.generate(config, messages)`, который возвращает только строку и **выбрасывает usage**. Rate limit там есть: 5 сообщений в минуту считается через `attempt_count`.
- `runner.py` — 20 строк, всегда бросает `RunnerUnavailable`. Это намеренно, флаг включения отсутствует.
- Миграция `0001_initial` — базовая ревизия, `downgrade` в CI идёт к ней.

## Задача

**1. Синхронизируй инструкции с реальностью.**

Дай `spec-tracer` задачу: пусть сверит утверждения в `README.md`, `UNIMPLEMENTED_STAGES.md` и `AGENTS.md` с фактическим кодом и составит список расхождений. Особое внимание — статусы, которые завышены, и функциям, описанным как работающие, но не реализованным.

**2. Закрой найденные расхождения.**

Раздай `content-author` или `implementer` точечные правки документации. Не переписывай документы целиком — только фактические ошибки.

**3. Зафиксируй baseline.**

Попроси `tester` запустить и записать точные команды и их вывод:

```
cd apps/api && python -m pytest -q
cd apps/web && npm run lint
cd apps/api && DATABASE_URL=sqlite:///./baseline.db python -m alembic upgrade head && python -m alembic check
```

Убедись, что временный `baseline.db` удалён после проверки.

## Ограничения

- Docker и PostgreSQL на этой машине не работают: виртуализация не включена, WSL2 недоступен. Не проси и не запускай `docker compose`, `alembic downgrade` на реальной БД, `psql`.
- PostgreSQL, row locking, изоляция Runner и end-to-end браузер остаются непроверенными. Называй их непроверенными, а не «должно работать».
- Не включай Runner флагом и не добавляй такой флаг.
- Не меняй доменную логику и не добавляй миграции в этой задаче. Только документация и baseline.

## Критерий готовности

Расхождения перечислены и исправлены, baseline записан с точным выводом команд, временные файлы удалены, непроверенное названо непроверенным.

В отчёте укажи: что расходилось, что исправлено, точный вывод проверок, что осталось непроверенным.
