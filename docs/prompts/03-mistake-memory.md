# Промт 03 — Память ошибок

## Роль

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md`, `.agents/skills/learning-domain/SKILL.md` и `.agents/skills/migration-safety/SKILL.md`.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Промты 00 и 02 **уже выполнены**: лестница подсказок, `HintReveal` и вывод `assisted` / `hint_count` в evidence изучи в коде сам. Не проверяй их и не спрашивай про них — работай дальше.

В спецификации (разделы 17.3 и 17.4) определены два вида памяти, и в проекте нет ни одного:

- **Mistake Memory** — повторяющиеся ошибки конкретного ученика, связь с навыками, подбор remediation.
- **Misconception Memory** — каталог типовых непониманий, не привязанных к одному ученику.

Текущее состояние: у `knowledge_check.py` есть `KnowledgeCheckResponse` с `is_correct` и `explanation`, но неправильный ответ нигде не накапливается. При повторном прохождении урока ученик получает тот же вопрос с тем же объяснением — персональной памяти ошибок нет.

Принятые решения — в `docs/decisions.md`.

## Задача

**1. Спроектируй модель.**

Дай `architect` задачу. Развести две сущности:

- `Misconception` — каталог авторского контента: код, текст ошибки, типичное неверное объяснение, skill ID, remediation-ссылка. Это контент, версионируется.
- `UserMistake` — факт конкретного ученика: ссылка на misconception, навык, урок, сколько раз встретилась, когда последний раз.

Ключевой вопрос, который должен решить `architect`: как отличить новую ошибку от повторной. Только по `(user, misconception)` или с учётом времени и соседних попыток.

**2. Определи источники ошибок.**

Дай `api-designer` задачу: где возникает ошибка сейчас и где появится позже. Обязательно проследи путь неверного ответа в knowledge check и в assessment — они уже есть в коде.

Отдельно: код ученика не исполняется, Runner fail-closed. Ошибки из запуска кода как источник **пока не подключай** — но модель должна быть к нему готова.

**3. Реализуй по миграции, затем записи, затем чтению.**

Дай `implementer` последовательные задачи:

- миграция создаёт каталог misconceptions с seed и таблицу user_mistakes;
- seed идемпотентный, безопасен при повторном запуске, не требует новых slug'ов контента;
- неверный ответ в knowledge check и assessment записывает факт ошибки;
- повторная ошибка того же типа увеличивает счётчик и обновляет время, а не создаёт дубликат;
- ошибка **чужого** ученика не пишется и не читается — проверка ownership обязательна.

**4. Подбери remediation.**

Дай `content-author` задачу: для каждой записи каталога нужен короткий текст, что делать дальше, и ссылка на упражнение. Никаких готовых решений.

**5. Покажи это ученику.**

Дай `ui-designer` задачу — где и как показывать повторяющиеся ошибки. Важно: интерфейс не должен выглядеть как оценка или ярлык «слабый». Разрешай это `frontend-implementer`.

**6. Покрой тестами.**

Дай `tester` задачу: тест на идемпотентность seed; тест на счётчик повторов; тест на то, что чужая ошибка не попадает в чужой профиль; тест на то, что запись ошибки **не меняет mastery напрямую** — mastery меняется только через `record_evidence`.

## Ограничения

- Docker и PostgreSQL не работают. Round trip миграций — на SQLite, временный файл, удалить после.
- Не включай Runner и не пиши код, исполняющий пользовательский ввод.
- Ошибка ученика — не приговор и не метрика вины. Не вводи поле «серьёзность» и не показывай счётчик ошибок как оценку способностей.
- Не своди мастерство к проценту ошибок.
- Не выдавай remediation с готовым решением.
- Миграция должна быть обратимой: `downgrade` откатывает, а не оставляет пустую таблицу.

## Критерий готовности

Каталог misconceptions засеян идемпотентно, ошибка ученика накапливается по типам, чужой доступ закрыт, mastery не меняется в обход evidence, remediation без готовых решений, миграция обратима, `pytest` и `npm run lint` зелёные.

В отчёте укажи: изменённые файлы, точный вывод проверок, чем «новая» ошибка отличается от «повторной» в твоей реализации, что осталось непроверенным.
