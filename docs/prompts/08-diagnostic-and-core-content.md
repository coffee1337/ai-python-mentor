# Промт 08 — Диагностика и волна 2 курса Python core

## Роль

Ты — оркестратор проекта AI-наставник Python Backend. Твоя работа — **декомпозиция и запуск агентов**, а не написание кода.

Прочитай `.agents/skills/task-router/SKILL.md`, `.agents/skills/content-authoring/SKILL.md`, `.agents/skills/learning-domain/SKILL.md` и `.agents/skills/backend-implementation/SKILL.md`.

**Действуй сразу.** Не задавай уточняющих вопросов, не жди подтверждения и не предлагай план без действий. Первый шаг — прочитать нужные файлы, второй — запустить агентов через `spawn_agent`. Ответ без запущенных агентов считается невыполненным.

Ограничение окружения: `max_concurrent_threads_per_session = 2`. Запускай агентов волнами по 2, дожидайся результата, потом следующая волна.

## Контекст

Все промты 00–07 выполнены. PostgreSQL 17 работает нативно, сеть исполнителей не развёрнута.

Проверенное состояние репозитория:

- 30 миграций Alembic (0001–0030), 29 файлов тестов, 16 уроков в `LESSONS`;
- **16 уроков покрывают только `python.core`**: variables → data-types → conditions → loops → functions → parameters → return-values → scope → mutability → strings → numbers → booleans → truthiness → comprehensions → lists → tuples;
- в графе **42 навыка `python.core`** — не покрыты `sets`, `dictionaries`, `slicing`, `iteration`, `exceptions`, `try_except`, `custom_exceptions`, `modules`, `packages`, `imports`, `testing_basics`, `assertions`, `pytest_basics`, `fixtures`, `typing_basics`, `type_hints`, `dataclasses`, `classes`, `objects`, `inheritance`, `composition`, и далее;
- в `knowledge_check_content.py` 106 записей CHECKS;
- **`assessment_content.py` содержит всего 6 вопросов и покрывает 2 навыка из 90** — `python.variables` и `python.conditionals`;
- `MAX_QUESTIONS=4`, `DIFFICULTY_PRIOR` по роли: beginner 0.15, student 0.3, junior 0.45.

**Главный разрыв этого промта:** новичок проходит диагностику, curriculum выдаёт ему уроки 1–3, и дальше диагностика не знает о нём ничего. Адаптивная оценка перестаёт работать ровно там, где она нужнее всего. Плюс курс обрывается на 16-м уроке из 42 core-навыков.

Принятые решения — в `docs/decisions.md`. В частности: клиент не решает, что он знает, а диагностика — это prior, а не точная оценка уровня.

## Задача

### 1. Спроектируй расширенную диагностику

Дай `architect` задачу спроектировать банк диагностических вопросов, покрывающий **все 42 навыка `python.core`**, с явной схемой выбора: сложность, порядок ветвления, ранняя остановка, использование `DIFFICULTY_PRIOR` по роли.

Требуется письменно ответить:

- сколько вопросов нужно в банке на 42 навыка и сколько максимуль�� задаётся за прогон (`MAX_QUESTIONS` сейчас 4 — это оставить или обосновать изменение);
- как вопрос отображается на навык и на difficulty, чтобы адаптивная ветка была осмысленной, а не случайной;
- как избежать утечки правильного ответа: клиент не получает `answer` (сейчас это соблюдается — не сломай);
- как устроен переход «ответил → следующий вопрос сложнее/проще», конкретно, а не общими словами;
- что делает диагностика при слабом результате: старт с `variables-v1`, а не экран «вы провалили тест».

### 2. Заполни волну 2 курса

Дай `architect` задачу спроектировать порядок уроков 17–32, покрывающих оставшиеся `python.core` до `python.testing_basics`, так, чтобы prerequisite не пропускались. Попроси объяснить порядок явно.

Затем дай `content-author` задачу писать уроки сериями по 3–4, продолжая с места, где остановился промт 06. Каждая серия — отдельный вызов агента.

Требования к каждому уроку:

- `LESSONS` в `apps/api/app/learning_content.py`: skill ID, prerequisite, цель, теория, пример с проверяемым выводом, checkpoint, misconception check, практика, вывод;
- вопросы в `knowledge_check_content.py` с правильным ответом и объяснением для **каждого** варианта;
- `ExerciseVersion` и лестница подсказок 1–5, если урок содержит практику;
- русский язык, уровень новичка, но без примитивности;
- примеры кода запускаемы, текстовый вывод совпадает с реальным.

### 3. Свяжи диагностику с контентом

Дай `implementer` задачу расширить `assessment_content.py` спроектированным банком и убедиться, что `assessment.py` корректно выбирает вопросы, пишет `assessment_runs`/`assessment_responses` и строит `UserSkill`-prior. Проверь, что вопрос без навыка в графе не попадает в банк.

### 4. Проверь качество

Дай `tester` задачу тесты на поведение:

- банк диагностики покрывает каждый навык `python.core` минимум одним вопросом;
- вопрос из банка разрешается в графе, его skill существует;
- `answer` не попадает в API-ответ;
- адаптивная ветка реагирует на ответы: правильный ответ повышает сложность следующего, неправильный — понижает;
- ранняя остановка соблюдает `MAX_QUESTIONS`;
- каждый урок имеет check; каждый урок с практикой имеет hint ladder;
- lesson → skill → prerequisite разрешаются, циклов нет.

## Ограничения

- Runner fail-closed: код ученика не исполняется. Практика проверяет чтение и объяснение фиксированного примера, а не запуск отправленного кода.
- Не меняй формулу mastery и не ослабляй `PASS_SCORE`.
- Не переименовывай существующие уроки `variables-v1`, `conditions-v1` и остальные 14 — только добавляй.
- Не расширяй scope: только Python core. `python.backend` — отдельный промт 09.
- Не выдавай проценты mastery как факт уровня.
