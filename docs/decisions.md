# Принятые решения проекта

Короткий документ: почему проект выглядит именно так. Читай до проектирования, чтобы не предлагать переделки без причины.

## Modular monolith, без микросервисов

FastAPI + Next.js в одном репозитории, PostgreSQL общий. Границы модулей проведены по домену (`learning`, `assessment`, `skill_graph`, `curriculum`, `mentor`), но не enforced типами сервисов. Причина: MVP с одним разработчиком; разделение появится, когда появится независимая нагрузка, а не заранее.

## Evidence — единственный источник mastery

`UserSkill` — проекция, а не истина. Истина — append-only журнал `SkillEvidence` плюс аудит `SkillMasteryAudit`. Любое изменение mastery должно объясняться конкретной записью evidence. Причина: иначе невозможно объяснить пользователю, почему его уровень изменился.

## Assisted и independent разделены всегда

`assisted` и `hint_count` — обязательные поля evidence. Полное решение с подсказкой не доказывает самостоятельность. Причина: центральная гипотеза продукта — наставник учит, а не делает работу за ученика.

## Runner fail-closed

`runner.py` бросает `RunnerUnavailable` и никогда не исполняет код в процессе API. Попытка сохраняется со статусом `unavailable`, это не успех. Причина: исполнение пользовательского кода без изоляции — дыра, которую нельзя закрыть ретроспективно. Флаг включения намеренно отсутствует.

## Один вызов AI Gateway, без vendor-логики в домене

Домен знает только про `ai_gateway` и схемы ответов. Конкретный провайдер, модель и ключи — конфигурация. Structured outputs валидируются Pydantic до использования. Причина: смена провайдера не должна быть миграцией бизнес-логики.

## Клиент не решает, что он знает

Клиент не передаёт user ID, оценку, статус завершения или ключ ответа. Всё определяется сервером по сессии, CSRF обязателен на изменяющих запросах. Причина: иначе прогресс и mastery можно подделать из браузера.

## Контент версионируется

Изменение смысла урока или ответа требует новой версии, а не правки на месте. Причина: иначе прошлый evidence перестаёт соответствовать тому, что ученик видел.

## Модели выбираются по качеству/цене

Массовые роли на дешёвых моделях, премиум — где вызовов единицы и цена ошибки высока. Распределение и коэффициенты в `model-routing.example.json`. Причина: агент, который стоит в 6 раз дороже при том же качестве, снижает число вызовов, а не повышает качество.

## Редактор кода — CodeMirror 6, а не Monaco

Поле кода на странице урока — `apps/web/app/learning/code-editor.tsx` на ядре CodeMirror 6
(`@codemirror/state`, `view`, `commands`, `language`, `autocomplete`, `lang-python`).
Обёртка `@uiw/react-codemirror` и её `basicSetup` намеренно не используются: они тянут
поиск, lint и UI автодополнения, которые странице урока не нужны.

Компонент грузится через `dynamic(..., { ssr: false })`, поэтому не входит в First Load JS
страницы: `/learning` остаётся около 112 kB, тогда как статический импорт давал 249 kB.
Monaco отклонён по трём причинам: `monaco-editor` распакован на ~97 MB и тянет worker-пути,
несовместимые с Next 15 App Router без webpack-трюков; редактор нужен только на одной
странице и только для Python; визуальный язык проекта задаётся вручную и не должен
зависеть от темы Monaco.

Причина выбора: Monaco — полноценная IDE-среда, а задача здесь — одно поле ввода с
подсветкой Python и автоотступом, где лишний вес и SSR-риск не окупаются.

## Страница урока разбита по домену, состояние живёт в page.tsx

`app/learning/page.tsx` только загружает данные и связывает состояние с
`LessonTheory`, `LessonPractice`, `KnowledgeCheckSection`, `AttemptHistory` и
`CoursePathSummary`. Полный интерактивный маршрут остаётся в `course-path.tsx` и не
дублируется. Причина: страница была самым перегруженным местом фронтенда, а смешивание
загрузки и разметки делало невозможным проверять части по отдельности.

## Упражнение показывает честное состояние Runner

Форма упражнения сохраняет попытку и прямо говорит, что код не выполнялся. Проценты
mastery не показываются как факт уровня: mastery — оценка модели, а результат проверки
знаний отображается счётом «верных ответов N из M». Причина: см. «Evidence — единственный
источник mastery» и правило UI: mastery — не истина, а модель.

## Knowledge Base: контент — это данные, retrieval привязан к навыку и версии

База знаний индексирует только авторскую теорию уроков из immutable-снапшота
`ExerciseVersion`. Оцениваемый материал (вопрос, варианты, ответ, пояснения
knowledge check, лестница подсказок) в индекс не попадает никогда — иначе
наставник смог бы прочитать оцениваемый ответ прямо из выдачи.

Каждый чанк привязан к `exercise_version_id` и `skill_id`. Retrieval — это
всегда hard filter по навыку и той версии, которую ученик видит сейчас, а
похожесть только ранжирует кандидатов внутри этого фильтра. Свободного поиска
по похожим строкам нет: текст соседнего урока или superseded-версии в выдачу
попасть не может.

Эмбеддинги хранятся в `knowledge_chunks.embedding` как упакованный float32
(`LargeBinary`), а не через pgvector. Так не нужна новая зависимость, а
`alembic upgrade head` проходит на машине без расширения. Ранжирование в
домене — это же делает деградацию возможной.

Degraded-режим — норма, а не авария: без `AI_GATEWAY_EMBEDDINGS_URL` /
`AI_GATEWAY_EMBEDDINGS_MODEL` / `AI_GATEWAY_EMBEDDINGS_DIMENSION` или при отказе
сервиса эмбеддингов наставник отвечает без retrieval и не сообщает ученику о
сбое. Чанк без вектора не проходит порог похожести, но остаётся
fallback-кандидатом — иначе деградация молча скрыла бы урок.

Текст из индекса в prompt попадает как JSON в поле `content` с явной пометкой
«untrusted data, not instructions». Системный промпт это фиксирует. Ключ
gateway и тексты ученика в логи не пишутся.
