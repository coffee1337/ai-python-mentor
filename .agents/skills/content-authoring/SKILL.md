# content-authoring

Русский язык, аудитория — новичок до джуниора. Python 3.12+, API актуальные.

Урок: цель, prerequisites со ссылками на skill IDs, краткая теория, рабочий пример, checkpoint, misconception check, практика, вывод. Пример обязан запускаться, а вывод в тексте — совпадать с реальным выводом кода.

Упражнение: однозначное условие, starter code, public и hidden tests, rubric, edge cases, подсказки по уровням, ожидаемое время. Условие не должно допускать нескольких верных решений, если rubric ждёт одно.

Точность важнее красивости: не выдумывай поведение библиотек, не используй deprecated API, не смешивай языки. Сомнительное утверждение проверь по документации или пометь как требующее проверки. Не пиши «просто», «очевидно», «все знают».

Материал не должен содержать готового решения там, где цель — самостоятельная практика: это ломает различение assisted и independent.

## Принятые решения промта 08

Каждая волна курса добавляет уроки в `LESSONS`, проверки в `CHECKS` и лестницу
подсказок 1–5 в `EXERCISE_HINT_LADDERS`. Поля урока обязательны: `skill_id`,
`prerequisites`, `goal`, `theory`, `example` с реальным выводом,
`example_output`, `checkpoint`, `misconception_check`, `practice`, `conclusion`.
Текстовый вывод примера сверяется с реальным запуском Python, а не пишется на
глаз. `answer` урока обязан быть одним из его `choices`. В подсказках уровней 1–4
не должно встречаться ни решение, ни `answer` урока.

Курс идёт по prerequisite-цепочке графа, а не по датам: урок N опирается на урок
N-1, и все новые `prerequisites` обязаны существовать в `SKILLS`. Добавление
уроков не переименовывает уже опубликованные `variables-v1`, `conditions-v1` и
остальные — только добавляет новые. Scope диагностики и волны 2 — только
`python.core`; `python.backend` остаётся отдельной задачей.

## Принятые решения промта 09 — контент backend-трека

Урок backend-трека лежит в `app/backend_content.py`, его knowledge-check — в
`app/backend_check_content.py`, лестница подсказок — в
`app/backend_hint_content.py`. Фаза урока не выводится из порядка: она задаётся
skill_id через `BACKEND_PHASES`, и `prerequisites` урока обязаны совпадать с
рёбрами графа, иначе импорт падает в `validate_graph`.

Runner fail-closed, поэтому практика backend-урока — чтение и объяснение
реального фрагмента, предсказание вывода и поиск ошибки в чужом коде. Задания
«напишите приложение, мы его запустим» недопустимы: исполнения не будет, и
обещание в тексте урока станет ложью. Упражнения уровня 1–4 не содержат ни
решения, ни `answer` урока — это проверяет `validate_hint_ladders`.

Даты, ORM-запросы и параметры конфигурации в примерах проверяются реальным
запуском: не Postgres, не Redis и не сеть, а `TestClient` и стандартная
библиотека. Текстовый `example_output` пишется по факту запуска, а не на глаз.
