# frontend-implementation

Next.js 15 App Router, React 19, TypeScript. Линтер проекта — `tsc --noEmit` (`npm run lint`), сборка — `npm run build`.

Инварианты клиента: клиент не передаёт user ID, оценку, статус завершения или ключ ответа — сервер определяет всё по сессии. Изменяющий запрос требует CSRF-токена. Ошибку показывай текстом для ученика, не выводя внутренние детали, статусы провайдера и ключи.

Стиль проекта: server components по умолчанию, client components только ради интерактивности или браузерного API. Стили — в `globals.css`; дизайн-система не расширяется без согласования с `ui-design-system`.

Каждая страница покрывает loading, error и empty, а не только успешный путь. Доступность обязательна: клавиатурная навигация, видимый фокус, контраст, aria на интерактивных элементах, поддержка `prefers-reduced-motion`. Адаптивность проверяй на узком и широком экране.

Не отключай правила линтера и не добавляй зависимости без отдельного согласования. Monaco не вводи без явного запроса.

## Редактор кода на странице урока

Поле кода — `app/learning/code-editor.tsx` на ядре CodeMirror 6. Обёртка
`@uiw/react-codemirror` запрещена: её `basicSetup` тянет поиск, lint и UI автодополнения.
Компонент подключается через `dynamic(..., { ssr: false })` — прямой импорт раздувает
First Load JS `/learning` со 112 kB до 249 kB.

Контракт компонента: `value`, `onChange`, `maxLength`, `disabled`, `readOnly`, `id`,
`label`, `describedBy`, `hint`. Лимит длины держит компонент, а не атрибут `maxlength`:
CodeMirror рисует contenteditable, у нативного поля нет `maxlength`. `disabled` и
`readOnly` переключаются через `Compartment`, чтобы не пересоздавать редактор и не терять
историю. Подсветка задаётся вручную по палитре проекта и обязана держать контраст
AA 4.5:1 на белой поверхности: `--green-deep` (#6f9142) даёт 3.62:1 и для текста не годится,
используется затемнённый #4a6b2c. Кольцо фокуса — минимум 3:1, тоже затемнённое.

Компонент только собирает текст попытки. Он не исполняет код и не добавляет клиентских
проверок правильности: runner fail-closed, решение принимает сервер.

Граница API важнее вёрстки: если контент имеет структурные поля (`goal`, `theory`, `checkpoint`, `practice`, `conclusion`), схема ответа обязана их отдавать, а страница — рендерить по секциям. Не сваливай структуру в один `body` и не добавляй поля в контент, не расширяя `response_model`: так уже потерялось 12 из 22 полей урока.

Ошибки загрузки не проглатывай: если AI-сервис недоступен, сообщи пользователю, что план построен без нейросети. Тихая подмена источника данных вводит в заблуждение.

Пиши файлы читаемо: одна логическая операция на строку, отступы, никаких ручных минификаций. Перед сдачей проверь, что в исходниках нет `????` вместо русского текста.
