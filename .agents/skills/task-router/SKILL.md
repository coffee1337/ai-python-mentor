# task-router

Определи класс задачи. Тривиальная/локальная — без делегации или implementer на самой дешёвой пригодной модели. Обычная фича — implementer, tester если есть риск поведения. Сущности/миграции/границы — architect → implementer → целевой tester/reviewer. Sandbox/auth/приватность/данные — security-reviewer и сильная модель. Эскалируй после двух неудачных целевых циклов или при высоком риске. Не дублируй анализ, передавай только нужные контекст и файлы. При параллельности назначай владельца файлов. Закрывай задачу проверяемым результатом.

## Роли

| Задача | Роль |
|---|---|
| экран, компонент, форма, вёрстка, состояния | frontend-implementer |
| визуальная система, иерархия, доступность, сравнение вариантов | ui-designer |
| эндпоинты, контракты, схемы, миграции | api-designer |
| массовый контент курса, серии уроков и упражнений | content-author |
| деплой, CI/CD, бэкапы, метрики, алерты | devops |
| сверка спецификации с кодом, карта пробелов | spec-tracer |
| доменные решения и границы модулей | architect |
| бэкенд-фичи | implementer |
| тесты и расследование падений | tester |
| независимое ревью diff | reviewer |
| sandbox, auth, PII, prompt injection | security-reviewer |

Правила выбора: одна роль — один результат. Дизайн до вёрстки: ui-designer задаёт решение, frontend-implementer реализует. Не запускай ui-designer на однострочный CSS-фикс. spec-tracer — до планирования спринта, а не после. devops — когда меняется инфраструктура, миграции или бэкапы, не на каждый релиз.

## Модели и стоимость

Качество важнее цены на сложном; экономия — на массовой рутине. Полные тиры и коэффициенты: `model-routing.example.json`.

| Класс задачи | Модель | Reasoning | Эскалация |
|---|---|---|---|
| тривиальная правка, форматирование | deepseek-v4.1-flash / space-bunny | high | implementer |
| рутинный scoped-код, диспетчеризация, точечные тесты | muse-spark-1.3 | medium/high | grok-4.7 |
| реализация фич, ревью, учебный контент | grok-4.7 | high / xhigh | gpt-6.1-sol при неоднозначности |
| сложная отладка, доменная логика на длинном контексте | gpt-6.1-sol (или glm-5.3 для 1M контекста) | high | claude-fable-5-1 |
| архитектурная развилка | gpt-6.1-sol | xhigh | claude-fable-5-1 / gpt-6-astra |
| security, миграции данных | gpt-6.1-sol | xhigh | claude-opus-5 |

Почему grok-4.7 и muse-spark-1.3, а не GPT: muse-spark-1.3 даёт 126% качества при коэффициенте 0,07 (эффективность ~1800 — лучшая в каталоге), grok-4.7 — 124% при 0,5 (~248) против ~31 у gpt-5.6-sol при том же классе качества. GPT оправдан там, где вызовов единицы и важна максимальная точность.

Правила: не понижать модель для рисков данных, sandbox и достоверности обучения. У grok и deepseek контекст 500k против ~1M у gpt/claude/glm — режь входные chunks или поднимай модель. Эскалировать по сигналу: неоднозначность, две неудачные попытки, необратимое изменение схемы, security boundary, нестабильные падения. Понижать — когда задача сводится к одному файлу по ясному требованию или нужен только повтор решения.
